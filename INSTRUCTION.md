## 1. Как устроена команда агентов

В каждом проекте настроена ролевая модель, зафиксированная в файле `AGENTS.md`:

```
                       ┌─────────────────────────┐
                       │    Вы (Пользователь)    │
                       └────────┬───────────────┬┘
    Вопросы, идеи,              │               │ Задачи разработки
    обсуждение фич              ▼               ▼
                  ┌──────────────────┐    ┌────────────────────────┐
                  │ 📋 Product Owner │    │ 👑 Team Lead           │
                  │  (Консультант)   │    │  (Оркестратор кодинга) │
                  └────────┬─────────┘    └───────────┬────────────┘
                           │                          │
                           ▼                          ▼
              Заносит новые задачи        Декомпозирует и назначает
              в To Do / Backlog           разработчикам
                           │                          │
                           │             ┌────────────┴───────────┐
                           │             ▼                        ▼
                           │       ┌───────────┐            ┌───────────┐
                           │       │ 💻 Backend│            │ 🎨Frontend│
                           │       └─────┬─────┘            └─────┬─────┘
                           │             │                        │
                           │             └───────────┬────────────┘
                           │                         ▼
                           │                    ┌───────────┐
                           │                    │ 🧪 QA     │ (Автотесты)
                           │                    └─────┬─────┘
                           │                          │
                           ▼                          ▼ (Тесты пройдены)
                    ┌───────────────────────────────────────┐
                    │           PROJECT_STATUS.md           │ ◄── Единая точка правды
                    └───────────────────────────────────────┘
```

- **📋 Владелец Продукта / Консультант (Product Owner / PM)**: отвечает на любые ваши вопросы во время работы, проводит брейншторм фич, помогает выбрать библиотеки и аккуратно пополняет бэклог задач в [PROJECT_STATUS.md](./PROJECT_STATUS.md).
- **👑 Тимлид (Главный агент)**: анализирует требования, составляет план архитектуры, ведет [PROJECT_STATUS.md](./PROJECT_STATUS.md), распределяет задачи и принимает результат.
- **💻 Разработчики (Backend/Frontend)**: пишут функционал, интерфейсы, API и базы данных.
- **🧪 Тестировщик (QA)**: пишет unit/интеграционные тесты, запускает их в консоли и не допускает закрытия задачи с багами.

## 2. Создание нового проекта из шаблона

У вас есть два равнозначных способа создать проект с уже настроенной командой агентов:

### Вариант А: Через диалог с агентом (из любой папки)
В новой сессии Antigravity просто напишите:
> *"Создай новый проект `shop-bot` из шаблона"*

Агент автоматически развернет шаблон, назовет проект и сразу перейдет в режим Тимлида.

### Вариант Б: Через терминал
Выполните команду в консоли:
```bash
~/projects/new_project.sh my-new-project
```
После этого перейдите в созданный проект:
```bash
cd ~/projects/my-new-project
agy
```

## 3. Ежедневный рабочий процесс (Workflow)

1. **Постановка задачи**:
   Вы даете задачу обычным языком:
   > *"Нужно сделать эндпоинт авторизации пользователей через JWT и написать на него тесты."*

2. **Работа Тимлида**:
   - Фиксирует задачу в `PROJECT_STATUS.md`.
   - Если задача объемная — подключает субагентов для параллельного написания кода или тестирования.

3. **Разработка и Тестирование**:
   - Разработчик пишет код.
   - Тестировщик пишет тест-кейсы и запускает тесты (`pytest` / `npm test`).
   - Если тест падает — код исправляется до «зеленого» статуса.

4. **Фиксация (Definition of Done)**:
   - Тимлид закрывает задачу в `PROJECT_STATUS.md`, делает git-коммит и отчитывается вам.

## 4. Параллельная работа: Консультант (Product Owner) во втором терминале

Одна из самых мощных возможностей — подключение агента-консультанта параллельно с процессом кодинга.

### Зачем это нужно?
Когда основная команда пишет объемный код или выполняет длинную задачу (например, прогоняет тесты или строит сложную фичу), терминал занят. Чтобы не ждать и не отвлекать разработчиков:
- Вы можете задать любой архитектурный или технический вопрос.
- Обсудить следующую фичу или дизайн интерфейса.
- Добавить новые задачи в проект, которые команда возьмет в работу следующими.

### Как запустить вторую сессию:
1. Откройте **вторую вкладку терминала** или соседнее окно.
2. Перейдите в ту же самую папку проекта и запустите:
   ```bash
   cd ~/projects/my-new-project
   agy
   ```
3. Обратитесь к агенту в роли Product Owner / Консультанта:
   > *"Привет! Выступай в роли Product Owner / Консультанта проекта. Я хочу обсудить следующую фичу..."*  
   > или  
   > *"Подскажи, какую библиотеку лучше выбрать для генерации PDF-отчетов и добавь эту задачу в бэклог"*

4. **Как происходит синхронизация**:
   - Агент-консультант обсуждает с вами детали и формулирует понятные критерии приёмки.
   - Он **дописывает задачи в секцию `### ⏳ Запланировано (To Do / Backlog)`** файла [PROJECT_STATUS.md](./PROJECT_STATUS.md).
   - Он **не трогает** текущие задачи `In Progress`.
   - Основной Тимлид в первой сессии, завершив текущий таск, автоматически увидит свежий бэклог в `PROJECT_STATUS.md` и сможет сразу взять новую задачу в работу!

## 5. Как продолжать работу после перезапуска ноутбука / сессии

### Шаг 1: Перед завершением работы (вечером или перед выключением)
Напишите агенту:
> *"Сохрани статус и закоммить"*

Что сделает агент:
- Зафиксирует текущий прогресс в `PROJECT_STATUS.md` (что сделано, что в процессе, текущие блокеры).
- Сделает коммит в git (`git add . && git commit -m "..."`).

### Шаг 2: На следующий день (после включения ноутбука)
1. Откройте терминал и перейдите в папку нужного проекта:
   ```bash
   cd ~/projects/my-new-project
   agy
   ```
   *(либо откройте эту папку в вашем редакторе кода/IDE).*

2. Напишите агенту любое из сообщений:
   > *"Продолжаем"*  
   > или  
   > *"На чём мы остановились? Какой статус?"*

3. **Что происходит автоматически**:
   - Агент видит `AGENTS.md` и действует как Тимлид.
   - Агент считывает `PROJECT_STATUS.md` и историю `git log`.
   - Он восстанавливает контекст и кратко сообщает:
     - Что было готово на прошлом этапе.
     - Какая задача сейчас в очереди / в процессе.
     - Предлагает конкретный следующий шаг.

## 6. Полезные команды и фишки Antigravity

- `/teamwork-preview` — запуск режима совместной работы команды автономных агентов над крупной задачей.
- `/plan` — попросить агента составить подробный пошаговый план перед реализацией.
- `/compact` — сжать контекст длинной беседы, освободив память диалога без потери ключевой сути.
- `/goal` — запуск глубокой автономной задачи с повышенной тщательностью.
